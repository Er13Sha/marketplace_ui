# Архитектура frontend

Frontend организован по Feature-Sliced Design (FSD). Код группируется не по техническому типу файла, а по ответственности и пользовательскому сценарию.

## Слои

```text
app/       Next.js entrypoints: маршруты, layout и route handlers
screens/    FSD-слой pages: законченные экраны приложения
widgets/   крупные переиспользуемые блоки интерфейса
features/  пользовательские действия и интерактивные сценарии
entities/  бизнес-сущности, их модели и API
shared/    технические примитивы без знания предметной области
```

Зависимости направлены сверху вниз:

```text
app → screens → widgets → features → entities → shared
```

Слой может использовать только себя и слои правее него. Срезы одного слоя не импортируют друг друга напрямую. Например, `screens/marketplace` может использовать `entities/catalog`, но `entities/catalog` не знает о marketplace.

## Структура среза

Внутри среза используются только нужные сегменты:

- `ui/` — React-компоненты и отображение.
- `model/` — состояние, хуки и чистые функции сценария.
- `api/` — запросы и gateway конкретной сущности или страницы.
- `lib/` — локальные вспомогательные функции.
- `index.ts` — публичный API среза.

Не добавляйте папки `domain`, `application`, `infrastructure` и `presentation`: они скрывают назначение кода и возвращают структуру Clean Architecture, от которой проект мигрировал.

## Что где лежит

- `entities/user`, `entities/catalog`, `entities/cart` и остальные сущности содержат типы данных и API соответствующих backend-контрактов.
- `features/catalog-filter` содержит поиск, фильтрацию и сортировку каталога.
- `features/product-images` содержит выбор, сортировку и назначение обложки изображений товара.
- `widgets/account-menu` и `widgets/cart-link` используются на нескольких экранах и не принадлежат одному маршруту.
- `screens/marketplace`, `screens/cart`, `screens/seller` и остальные screens собирают законченный экран из widgets, features и entities.
- `screens/` назван так из-за Next.js: верхнеуровневый `pages/` зарезервирован для Pages Router. По ответственности `screens/` — это FSD-слой `pages`.
- `app/*/page.tsx` остаются тонкими Next.js-адаптерами и импортируют только публичный API страницы.

## Правила поддержки

1. Внешний код импортирует срез через его `index.ts`: `@/entities/catalog`, `@/features/catalog-filter`, `@/screens/marketplace`.
2. Запросы к backend не пишутся в JSX. API сущности живёт в `entities/*/api`, а API экрана — в `screens/*/api`.
3. Чистые расчёты и преобразования находятся в `model` или `lib`, а не в компонентах.
4. Если действие переиспользуется на разных экранах, оно оформляется как `features`; если блок интерфейса собирает несколько частей — как `widgets`.
5. Новый код не должен импортировать внутренний путь другого среза вроде `@/entities/catalog/model/product`. Используйте публичный API среза.
6. `shared` не импортирует код предметной области. В него попадают только общие API-клиенты, форматтеры и UI-примитивы.
